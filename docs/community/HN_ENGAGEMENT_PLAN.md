# HN Engagement Plan

**Goal:** Build legitimate HN participation history so a future Show HN submission is natural, not promotional.

**Principle:** Contribute technical insight first. The Show HN will come when the account is a known participant.

---

## HN Culture Guidelines

| Rule | Why |
|------|-----|
| **Lead with substance** | HN readers value technical detail over positioning |
| **Be curious, not certain** | "I think" > "This is why" |
| **Acknowledge limitations** | "We haven't solved X yet" builds trust |
| **Don't promote** | Linking your project is fine when it's directly relevant to the discussion. Linking it in every comment is not. |
| **Read before commenting** | Understand the thread's tone before contributing |
| **Don't argue with downvotes** | If a comment is downvoted, consider why instead of defending it |
| **Cite sources** | Links to papers, repos, or documentation strengthen arguments |
| **No "first post"** | Don't announce this is your first comment |

---

## Types of Comments Worth Contributing

| Type | Example |
|------|---------|
| **Technical explanation** | "The A2A protocol handles task delegation through a shared Card schema. One challenge is that Cards are static — there's no heartbeat or liveness check." |
| **Engineering experience** | "We ran into this exact issue with SQLite concurrent writes. Our solution was to keep writes sequential and accept read replicas aren't needed at our scale." |
| **Nuanced disagreement** | "I think the trade-off is more subtle. While X approach works for Y, it breaks down when Z happens because..." |
| **Helpful context** | "There's a related project doing something similar: [link]. They focus on [difference]." |
| **Answering questions** | If someone asks about agent discovery, explain what exists and what's missing |

| 2 | Comment on 5 threads. One substantive technical comment. | 20 min/day |

## What Not To Do

- Do not create multiple accounts
- Do not ask others to upvote
- Do not post "As the creator of A2A Hub..." in unrelated threads
- Do not complain about the restriction
- Do not rush the process
